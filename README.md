## 这是什么

一个执行期长达 20 年的指数定投计划的公开台账：

- 每月理论目标 **3000 元**，投入三个标的：**纳斯达克100、黄金、中证500**；
- 不平均分配，而是按各标的相对自身长期均值的估值位置动态分配——**越便宜多买、越贵少买**；
- 2026 年 4 月起执行。当前实际节奏为每月定投基数 300 元、当月投入超过 300 元的部分计为补投，历史欠下的目标缺口单独记账、逐步补足。

## 功能

- **概览台账**：累计投入、理论目标、缺口、完成率、三标的累计投入占比、每月实投走势；
- **逐月明细**：按年份分组折叠展示，每月含理论分配、实际投入分拆、定投/补投构成与当月缺口；数据存于仓库文件 `data/months.json`，页面打开时自动读取渲染、当月与累计缺口自动计算（读取失败则回退到页面内嵌的静态快照并标注）；
- **每月分配计算（自动更新）**：数据由 GitHub Actions 每个工作日收盘后自动抓取、双源校验后写入仓库（见下方「数据自动更新」），页面打开时优先读取这份数据；仓库数据不可用时，浏览器再尝试直连东方财富现场计算；仍失败则回退到最近一次快照并标注日期，不显示错误数字。也可手动修改任意点位/均值试算，计算只在本页进行、不保存。
- **已投收益估算**：按指数点位估算已投入部分的当前估值与收益率（每笔买入价取当月计算参考点位、当前价取最近已完成收盘），每日随行情自动更新；附「收益走势」图（收益率 % 双线对比上证/沪深300/创业板指，全部/今年/本月/本周切换，收益数字红正绿负）；为指数口径估算，不含基金费用、跟踪误差与汇率影响，非基金账户实际收益；
- **预期回报测算**：可改每月金额与年限，按 4% / 6% / 8% / 10% 恒定年化假设测算累计本金、预期收益与期末资产（每月月末投入、月复利）；恒定年化只是数学假设，非收益预测或承诺。

## 计算口径

**估值动态分配公式**

```
位置权重 = 30 月均值 ÷ 当前点位
分配金额 = 月度总金额 × 该标的权重 ÷ 三权重合计
```

权重越高说明该标的相对其长期均值越便宜，分得越多。金额取整采用最大余数法，三者合计严格等于月度总金额。

**数据与口径约定**

| 项目 | 约定 |
| --- | --- |
| 纳斯达克100 | 东方财富 secid `100.NDX100`，点位取最近已完成交易日收盘 |
| 中证500 | 东方财富 secid `1.000905`，北京时间 15:00 前剔除当日未收盘 bar |
| 黄金 | 上海金 Au9999（东方财富 secid `118.AU9999`，人民币/克）；15:30 前剔除当日 bar，夜盘提前生成的下一交易日 bar 一律剔除 |
| 30 月均值 | 滚动口径：截至最新收盘日、往前 30 个月的全部每日收盘算术平均，随时间推进 |
| 每月正式分配 | 每月第一个 A 股交易日按当时最新数据计算，记入月度台账 |
| 已投收益估算 | 指数口径：买入价取各月计算参考点位（`months.json` 的 `buy`），当前价取最近已完成收盘；黄金 2026-04~11 按 COMEX、2026-12 起按 Au9999 分口径比值计算 |

**历史口径变更**

- 黄金数据源自 **2026-11-06** 起由 COMEX 黄金（美元/盎司）改为上海金 Au9999（人民币/克）；2026-04 至 2026-11 的历史分配按当时 COMEX 口径保留，不回溯修改。
- 2026-04 至 2026-09 的理论分配为 2026-11-06 按原公式与真实历史行情补算；10 月、11 月为当月正式计算值。
- 定投/补投划分：每月定投基数 300 元，实际投入超过 300 元的部分一律计为补投（2026-11-06 起执行此口径）。

## 数据自动更新

本仓库带一条 GitHub Actions 流水线（`.github/workflows/daily-update.yml`），无服务器、零成本：

- **何时跑**：每个工作日北京时间 09:00（A 股 09:30 开盘前：中证500 与上海金用上一个交易日收盘、纳指用今晨刚收盘的美股数据，都是已完成收盘；当天交易时段内即可照此分配买入），也可在 Actions 页面手动触发；
- **做什么**：`scripts/fetch_data.py` 从东方财富拉取三个标的的日 K，按上述口径算出最新点位、滚动 30 月均值、权重与分配；
- **双源校验**：最新收盘价再与第二来源交叉核对——纳指100、中证500 用腾讯行情，黄金用东方财富实时报价通道并叠加单日涨跌 ±3.5% 合理性检查；任一校验不通过，流水线直接报错退出，**不发布坏数据**；
- **产物**：`data/latest.json`（最新一期完整数据，页面读取）与 `data/history.csv`（每日历史，一日一行，长期留档）；数据无变化时不产生提交。
- **已投收益估算**：同一次运行还执行 `scripts/fetch_returns.py`，按各月买入参考点位与最新已完成收盘估算已投部分的当前估值与收益率，写入 `data/returns.json`（页面「已投收益估算」读取）；该步独立校验、失败不阻断主数据更新，保留上一版数据；

另有一条**月度流水线**（`.github/workflows/monthly-update.yml`），负责月度台账的自动新增：

- **何时跑**：每月 1–12 日北京时间 09:05 触发，`scripts/monthly_calc.py` 内部判断是否为当月第一个 A 股交易日（或其后 3 天内的补跑窗口），不是则安静退出；也可在 Actions 页面手动触发（可勾选 force 跳过窗口判断）；
- **做什么**：按**每月正式口径**（30 个月末收盘均值 ÷ 最新已完成收盘、最大余数法取整）计算当月理论分配，追加到 `data/months.json`（实际投入暂为空），并提交回仓库——页面下次打开即显示新月份；
- **口径与校验**：纳指100 用 Yahoo Finance `^NDX`（东方财富兜底），中证500 用东方财富，黄金自 2026-12 起用上海金 Au9999；最新收盘同样经双源校验（腾讯行情 / 东方财富实时通道昨收 + 黄金单日涨跌合理性），不通过不写入；
- **实际投入**：由维护者在每月买入后补填到 `data/months.json` 对应月份，页面随即自动更新当月与累计缺口。
- **历史复算**：2026-04~11 各月的计算依据（`basis`：30 月窗口、均值、计算时点点位与日期、权重）已由 `scripts/backfill_basis.py` 按同一口径复算回填，8 个月复算分配与已录分配全部一致（`verified: true`）；随时可运行 `python3 scripts/backfill_basis.py --check` 独立复算校验。注意黄金历史均值用 Yahoo `GC=F`（与当年正式计算同源），东方财富 `101.GC00Y` 月 K 的月末取数惯例不同、复算对不上，不可混用。

## 项目结构

```
.
├── index.html                  # 站点全部内容：单文件、零依赖、仅使用系统字体
├── scripts/
│   ├── fetch_data.py           # 每日：抓取行情、双源校验、计算最新分配（仅用 Python 标准库）
│   ├── fetch_returns.py        # 每日：按买入参考点位估算已投收益并生成逐日收益序列，写入 returns.json（仅用 Python 标准库）
│   ├── monthly_calc.py         # 每月：第一个交易日按正式口径计算当月分配并追加台账（标准库 + chinese-calendar）
│   └── backfill_basis.py       # 审计：按同口径复算历史月份 basis 并校验（手动运行，--check 只校验不写）
├── data/
│   ├── latest.json             # 最新一期分配数据（Actions 每日更新）
│   ├── history.csv             # 每日分配历史留档
│   ├── returns.json            # 已投收益估算（Actions 每日更新）
│   └── months.json             # 月度台账数据（理论分配 Actions 每月自动追加，实际投入人工补填）
├── .github/workflows/
│   ├── daily-update.yml        # 工作日 09:00（北京时间）定时运行并提交数据
│   └── monthly-update.yml      # 每月 1–12 日 09:05（北京时间）触发，第一个交易日自动追加当月台账
├── README.md                   # 本文件
├── CHANGELOG.md                # 更新日志
├── LICENSE                     # MIT License
└── .gitignore
```

`index.html` 为自包含单文件：样式与脚本全部内联，不引用任何外部字体或库（避免外部资源阻塞渲染）。分配计算的数据由访问者浏览器在打开页面时实时获取；台账数据存于 `data/months.json`，页面打开时读取渲染，读取失败时回退到页面内嵌的静态快照（截至 2026-11）。

## 更新方式

- 分配数据：GitHub Actions 每个工作日自动更新（见「数据自动更新」），不需要人工操作；
- 台账理论分配：每月第一个 A 股交易日由月度流水线自动计算并追加到 `data/months.json`；
- 台账实际投入：每月买入确认后，由维护者把实际金额补填到 `data/months.json` 对应月份，页面打开即为最新，网址不变；
- 每次更新记录在 [CHANGELOG.md](CHANGELOG.md)。
